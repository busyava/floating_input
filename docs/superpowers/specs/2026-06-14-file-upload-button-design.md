# FloatingInput: кнопка «＋» для отправки файлов домой

Дата: 2026-06-14
Статус: согласовано (брейншторм с Денисом)

## Проблема

Денис подключается к домашнему компьютеру с телефона (с работы) через SSH
`hallwss` и общается с Claude Code в терминале Termux. Нет удобного способа
передать Claude картинку или файл с телефона. Существующие пути (scp вручную,
веб-filebrowser) требуют либо набора команд на телефоне, либо зависят от
доступности публичного сайта.

В оверлее FloatingInput слева есть кнопка `btnToggleTemplates` (стрелка ▲/▼),
разворачивающая ленту текстовых шаблонов, которой Денис не пользуется.

## Цель

Заменить неиспользуемую кнопку шаблонов на «＋»: один тап → выбор файла →
файл заливается домой → **в буфер обмена попадает полный путь к файлу на
домашнем компьютере**, как его видит Claude. Денис длинным тапом вставляет путь
в чат, Claude делает `Read` по этому пути.

## Ключевое ограничение транспорта

На работе интернет идёт только через VLESS+XHTTP. Сырой SSH ломается (XHTTP
искажает протокол) — ради этого и существует hallwss (SSH, обёрнутый в
WebSocket поверх `wss://ha.vkrutina.online`). **Обычный HTTPS на `*.vkrutina.online`
с работы проходит нормально** — на этом и держится hallwss.

Вывод: транспорт загрузки — обычный HTTPS POST на `*.vkrutina.online`. Это
тот же проверенный канал, что несёт hallwss, и он **не требует никаких правок
nginx/sshd/firewall** — безопасно делать даже из удалённой сессии (нет риска
оторвать себе hallwss).

## Архитектура

```
[Телефон] FloatingInput "＋"
   │ системный file picker
   │ HTTPS POST (login → upload)
   ▼
files.vkrutina.online  (filebrowser, уже развёрнут, nginx на minipc)
   │ пишет в SMB-шару workshop → claude-inbox/
   ▼
TrueNAS  workshop/claude-inbox/<unique>
   │ (та же шара примонтирована на Hallcomputer по CIFS)
   ▼
Hallcomputer:/home/denis/truenas/workshop/claude-inbox/<unique>
   ▲ этот путь FloatingInput кладёт в буфер обмена
   │
[Телефон] Денис вставляет путь в чат → Claude делает Read
```

Компоненты, каждый с одной задачей:

- **UI (FloatingService):** кнопка «＋» вместо `btnToggleTemplates`; запуск
  системного пикера файла; тосты статуса.
- **Загрузчик (новый класс, напр. `FileUploader`):** инкапсулирует HTTP к
  filebrowser — login → token → upload. Не знает про UI, принимает `Uri` и
  колбэк результата (успех с путём / ошибка с причиной).
- **filebrowser (сервер, уже есть):** принимает файл, кладёт в
  `workshop/claude-inbox/`. Новой серверной разработки нет.

## Поток «＋»

1. Тап «＋» → системный пикер (`ACTION_OPEN_DOCUMENT`, тип `*/*` — любой файл).
2. Получаем `content://`-Uri и исходное имя файла.
3. Формируем **детерминированное уникальное имя:**
   `ГГГГММДД-ЧЧММСС-<очищенное-исходное-имя>`. Очистка: пробелы/кириллица/спецсимволы
   → безопасный набор (`[A-Za-z0-9._-]`), чтобы путь был предсказуем и не зависел
   от того, как filebrowser обработает имя.
4. `FileUploader`:
   - `POST https://files.vkrutina.online/api/login` `{username, password}` →
     токен (зашит в debug-апку).
   - `POST https://files.vkrutina.online/api/resources/claude-inbox/<unique>?override=true`
     с телом файла и заголовком `X-Auth: <token>`.
     > Уточнено при реализации (Task 1): scope аккаунта filebrowser — корень со
     > всеми шарами, поэтому фактический путь `workshop/claude-inbox/<unique>`
     > (с префиксом шары). См. `UploadConfig.REMOTE_DIR`.
5. **Успех:** в буфер обмена кладём
   `/home/denis/truenas/workshop/claude-inbox/<unique>` + тост «скопирован путь».
6. **Ошибка** (нет сети, не тот код ответа, исключение): тост с причиной; в
   буфер ничего не кладём.

## Конфигурация (зашита в debug-апку)

- Базовый URL filebrowser: `https://files.vkrutina.online`
- Логин/пароль: отдельный аккаунт filebrowser для апки (создать при подготовке).
- Целевая папка в шаре: `claude-inbox` (создать в filebrowser при подготовке).
- Префикс пути на компе: `/home/denis/truenas/workshop/claude-inbox/`.

Хранить как константы (можно вынести в один объект `UploadConfig`). Это debug-сборка
для личного использования — секреты в коде приемлемы, но держим их в одном месте.

## Удаляем

Функциональность шаблонов больше не нужна — выпиливаем, чтобы не таскать мёртвый
код: `loadTemplates`/`saveTemplates`, `setupTemplates`, `showTemplateMenu`,
`showTemplateEditDialog`, поля `templates`/`templatesVisible`, вью
`templatesScroll`/`templatesContainer`/`btnToggleTemplates` из лейаута и связанные
строки/drawable, относящиеся только к шаблонам.

## Обработка ошибок

- Нет разрешения/служба спецвозможностей — не относится к загрузке (буфер
  работает без неё); путь просто окажется в буфере.
- Сетевые ошибки и не-2xx ответы filebrowser → тост, путь в буфер не пишем,
  чтобы Денис не вставил путь к несуществующему файлу.
- Большие файлы: грузим потоково из `InputStream` Uri, не держим в памяти целиком.

## Тестирование

- Юнит: генерация уникального имени (очистка пробелов/кириллицы/коллизий,
  формат `ГГГГММДД-ЧЧММСС-…`).
- Юнит: сборка целевого пути для буфера из имени и префикса.
- Ручная проверка (Денис): тап «＋» → выбор фото → путь в буфере → вставка в
  чат → Claude видит файл.

## Подготовка инфраструктуры (один раз, до/во время реализации)

1. Проверить, что `files.vkrutina.online` открывается в браузере телефона **с
   работы** (подтверждает, что HTTPS-транспорт проходит фильтр).
2. Завести в filebrowser папку `claude-inbox` в шаре `workshop`.
3. Завести в filebrowser отдельный аккаунт для апки (права: запись в
   `claude-inbox`).
4. Подтвердить чтение `~/truenas/workshop/claude-inbox/` на Hallcomputer
   (шара уже примонтирована по CIFS — проверено).

## Сборка и выкладка

- `./gradlew assembleDebug`, debug-подпись (обновление встаёт поверх без удаления).
- Растущий versionCode/versionName.
- APK в filebrowser: `workshop/apk/floating-input-<ver>.apk` (как у 1.1).
- После установки проверить, что служба спецвозможностей FloatingInput включена
  (для вставки текста; на загрузку не влияет).

## Явно НЕ делаем (YAGNI)

- Встроенный SSH/SFTP-клиент в апке поверх websocket (вариант C из брейншторма) —
  слишком много кода.
- Загрузку через Termux/scp (вариант B) — запасной путь, не реализуем, пока
  HTTPS работает.
- Автопостинг пути в чат вместо буфера — буфер даёт Денису контроль момента
  вставки.
- Прогресс-бар, очередь, ретраи — одиночная синхронная загрузка с тостом.
